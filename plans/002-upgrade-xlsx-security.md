## Why this matters

The app depends on `xlsx@0.18.5` (SheetJS) in `package.json:64`. That published
npm version has two known, unpatched advisories: **prototype pollution**
(GHSA-4r6h-8v6p-xvw6) and **ReDoS** (GHSA-5pgg-2g8v-p4x9). Both are only fixed
in SheetJS **0.20.x**, which the maintainers publish from `https://cdn.sheetjs.com`,
not the npm registry. This app feeds *user-uploaded* `.xlsx` files into the
parser (the budget bases are bundled, but nothing stops a user pointing the
tooling at an arbitrary workbook), so a malicious workbook is a realistic
trigger. Prototype pollution in a client bundle can corrupt object behavior
app-wide. Upgrading to the patched SheetJS build removes both advisories.

Note: `xlsx-js-style@1.2.0` (used only for the styled *export* in
`page.tsx:57`) is a separate fork and is **out of scope** here — it only writes
files this app generates, it never parses untrusted input. Leave it.

## Steps

### Step 1: Repoint `xlsx` to the patched SheetJS build

SheetJS publishes patched versions only from its own CDN. Update the `xlsx`
entry in `package.json` dependencies to the CDN tarball for the latest 0.20.x:

```json
"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz",
```

(Confirm the latest 0.20.x tarball URL at https://cdn.sheetjs.com/ — use the
newest `0.20.*` listed. Do NOT downgrade below 0.20.2, the first version with
both advisories patched.)

Then reinstall: `bun install` (or `npm install`).

**Verify**: `node -e "console.log(require('./node_modules/xlsx/package.json').version)"`
→ prints `0.20.x`.

### Step 2: Confirm nothing broke

The used API (`XLSX.read`, `XLSX.utils.sheet_to_json`) is identical across
versions, so no code changes are expected.

**Verify**:
- `npx tsc --noEmit` → exit 0.
- `npx vitest run` → all pass (if plan 001 is merged; otherwise skip).
- `bun run build` → completes without errors referencing `xlsx`.

### Step 3: Confirm the advisory is gone

**Verify**: `bun pm audit` (or `npm audit`) → no high/critical advisory
attributed to `xlsx`. (Other unrelated advisories may remain; only `xlsx` must
be clear.)

## STOP conditions

Stop and report (do not improvise) if:

- The CDN tarball URL 404s or the install fails to fetch it (network-restricted
  environment) — report so a human can vendor the tarball or whitelist the CDN.
- After upgrade, `XLSX.read` or `sheet_to_json` throws or returns a different
  shape on the bundled bases (the four files in `public/`) — this would be a
  breaking API change; report rather than rewriting parsers.
- `tsc` reports new type errors from the `xlsx` types after upgrade.

## Maintenance notes

  tarball into the repo and point the dependency at the local path.
